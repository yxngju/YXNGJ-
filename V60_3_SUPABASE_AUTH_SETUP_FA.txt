YXNGJU V60.3 — SUPABASE AUTH INTEGRATION

مبنای کار: بسته V60.2 ارسالی کاربر.

انجام‌شده:
- اتصال صفحه account.html به پروژه Supabase موجود با کلید Publishable عمومی.
- فعال‌سازی دکمه ورود با Google از طریق signInWithOAuth و بازگشت به account.html.
- اضافه‌کردن ورود ایمیل/رمز، ثبت‌نام ایمیلی و درخواست بازیابی رمز.
- نمایش وضعیت نشست و خروج از حساب.
- بررسی نقش از جدول admin_users؛ فقط نقش owner با ایمیل مالک به لینک پنل مدیریت دسترسی نمایشی می‌گیرد.
- افزودن کنترل سمت مرورگر برای جلوگیری از نمایش پنل admin به کاربران عادی.
- استفاده از trigger و RLS موجود در پروژه؛ هیچ جدول یا policy جدیدی ساخته نشد.
- کلید service_role یا secret در فایل‌های عمومی قرار نگرفته است.

تأییدشده از سمت Supabase:
- پروژه فعال و URL صحیح است.
- کلید Publishable عمومی دریافت شد.
- جدول‌های profiles، admin_users، contact_messages و login_events موجود و RLS فعال است.
- trigger روی auth.users پروفایل می‌سازد و فقط برای ایمیل benyaminabadi7@gmail.com پس از تأیید ایمیل، نقش owner ایجاد می‌کند.
- Security Advisor در زمان بررسی lint امنیتی گزارش نکرد.
- Redirect URLهای مجاز باید شامل این آدرس باشند:
  https://yxngju.github.io/YXNGJ-/account.html
  https://yxngju.github.io/YXNGJ-/

محدودیت‌ها و تست لازم:
- این بسته هنوز روی GitHub Pages منتشر نشده است.
- ورود واقعی Google، ایمیل تأیید، بازیابی رمز و نشست روی دستگاه کاربر هنوز قابل تست نیست؛ پس از انتشار باید آزمایش شوند.
- صفحه admin.html همچنان پیش‌نمایش است و قابلیت‌های مدیریت واقعی کاربران/محتوا را ندارد.
- کنترل نمایش admin در مرورگر به‌تنهایی مرز امنیتی محسوب نمی‌شود؛ داده‌های واقعی باید فقط از طریق RLS و عملیات سمت سرور محافظت شوند.
- این بررسی، ممیزی ایستا و بررسی تنظیمات موجود Supabase است؛ تست نفوذ مستقل انجام نشده است.

مراحل انتشار:
1) ZIP را استخراج کن.
2) محتوای پوشه yxngju_site_v48_chrome_glass را جایگزین فایل‌های همان پوشه در مخزن فعلی GitHub کن.
3) با GitHub Desktop روی همان branch اصلی Commit و Push کن.
4) پس از انتشار، ابتدا صفحه account.html را باز کن و ورود با Google را با ایمیل مالک آزمایش کن.

تکمیل تنظیم حساب در V60.5:
- ورود ایمیلی Supabase به Gmail محدود نیست؛ هر ایمیل معتبر و تحت کنترل کاربر قابل استفاده است.
- yxngj-admin نام نمایشی پیشنهادی برای ایمیل مالک فعلی است، نه نام کاربری ورود. ورود همچنان با ایمیل و گذرواژه انجام می‌شود.
- پس از ورود، کاربر می‌تواند نام نمایشی و گذرواژه را از بخش تنظیم حساب تغییر دهد. نام نمایشی در user_metadata ذخیره می‌شود و مبنای نقش یا مجوز نیست.
- این تغییرات حساب ادمین را از راه دور در Supabase ایجاد نمی‌کند. پیوند پنل در برنامه بر اساس نقش owner در admin_users است، نه Gmail؛ اما trigger و allowlist پایگاه‌داده فعلی هنوز به ایمیل مالک ثبت‌شده در Supabase وابسته‌اند. برای استفاده از ایمیل غیر Gmail به‌عنوان مالک، ابتدا حساب آن ایمیل را تأیید کن و سپس allowlist/trigger را از مسیر امن SQL مدیریتی به همان حساب تغییر بده یا نقش را به user_id درست اختصاص بده. کاربر نباید بتواند نقش خودش را از مرورگر تنظیم کند.
- از گذرواژه‌های شناخته‌شده یا کوتاه مانند 1234 استفاده نکن؛ گذرواژه قوی را از مسیر دعوت/بازیابی تنظیم کن. هیچ گذرواژه یا service_role key را در فایل‌های عمومی یا GitHub قرار نده.
- قبل از انتشار، تأیید ایمیل، ورود با ایمیل غیر Gmail، ذخیره نام نمایشی، تغییر گذرواژه و بازیابی گذرواژه را روی سایت مستقرشده آزمایش کن.
