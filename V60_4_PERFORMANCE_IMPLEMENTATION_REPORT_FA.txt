گزارش نسخه V60.4 — بهینه‌سازی قابل اجرا روی GitHub Pages
تاریخ: 2026-11-22

مبنای کار:
فایل ورودی YXNGJU_V60_3_SUPABASE_AUTH_INTEGRATION.zip بررسی و همین پروژه استاتیک توسعه داده شد.
میزبانی فعلی GitHub Pages است؛ در این بسته سرور اختصاصی یا بک‌اند برنامه‌ای وجود ندارد.

انجام‌شده در این نسخه:
1) افزودن v60-performance.css برای نمایش حالت اسکلت/placeholder سبک روی تصاویر lazy و وضعیت بارگذاری سند.
2) افزودن performance.js شامل ابزارهای عمومی fetchOnce برای جلوگیری از درخواست GET تکراری هم‌زمان، debounce برای جستجو/پیشنهاد خودکار و fetchWithTimeout برای درخواست‌های بیرونی. این توابع باید از ماژول‌های API فراخوانی شوند؛ در نسخه فعلی جستجوی API مستقل وجود ندارد که بتوان همه‌جا به‌طور خودکار به آن متصل کرد.
3) افزودن loading="lazy" و decoding="async" به تصاویر فاقد این ویژگی در صفحات HTML؛ تصویر دارای fetchpriority="high" دست‌نخورده ماند.
4) افزودن defer به اسکریپت‌های دارای src برای جلوگیری از مسدود کردن تجزیه HTML؛ ترتیب اسکریپت‌ها حفظ شده است.
5) افزودن اسکریپت عملکرد به صفحات HTML اصلی، حساب، مدیریت، بازی و فهرست بازی‌ها.
6) بیشتر تصاویر سایت از قبل WebP بودند. فایل‌های PNG بازی و تصاویر مرجع اصلی حفظ شدند تا شفافیت/کیفیت و منابع اصلی آسیب نبینند؛ تبدیل گروهی کورکورانه انجام نشد.

محدودیت‌های محیط فعلی و کارهای نیازمند زیرساخت:
- GitHub Pages هاست استاتیک است؛ امکان راه‌اندازی Redis، صف پس‌زمینه، worker، load balancer، connection pooling، تنظیم gzip/Brotli در وب‌سرور، OpenTelemetry سمت سرور، اجرای کوئری دیتابیس و رفع N+1 از داخل این ZIP وجود ندارد.
- در کد فعلی، مسیرهای بک‌اند/جستجوی API و کوئری‌های فهرستی قابل شناسایی برای اصلاح N+1 وجود ندارد؛ احراز هویت Supabase به‌تنهایی به معنی وجود API دیتایی نیست.
- CDN: فایل‌های استاتیک از زیرساخت توزیع GitHub Pages سرو می‌شوند؛ CDN دلخواه و تنظیمات cache-control سفارشی در این مخزن قابل پیکربندی نیست.
- SSG/SSR: صفحات موجود HTML استاتیک هستند و در زمان build/از قبل تولید شده‌اند. رندر سمت سرور پویا نیازمند میزبان/فریم‌ورک بک‌اند است.
- تقسیم کد: اسکریپت‌های صفحات جداگانه‌اند، اما تبدیل معماری فعلی به bundler و code-splitting پیشرفته نیازمند مهاجرت build system است.
- Virtualization برای لیست‌ها تنها وقتی لازم است که فهرست طولانی داده‌ای و رندر پویا وجود داشته باشد؛ موردی با این نیاز در صفحات استاتیک فعلی احراز نشد.
- حذف پکیج‌های بلااستفاده: package.json/lockfile و node_modules در ورودی وجود ندارد؛ بنابراین چیزی حذف نشد.
- Real User Monitoring و تست واقعی روی گوشی/شبکه کند: از این محیط امکان اجرای مرورگر واقعی و جمع‌آوری داده کاربران وجود ندارد. هیچ نتیجه آزمایش میدانی ادعا نمی‌شود.
- فونت: فایل فونت محلی قابل‌انتقال/معتبر در بسته پیدا نشد؛ برای جلوگیری از جایگزینی ناخواسته فونت، فایل جدیدی اضافه نشد.

نتیجه:
این نسخه بهینه‌سازی‌های فرانت‌اندی را که با GitHub Pages سازگارند اعمال می‌کند و ابزارهای کمکی API را آماده می‌گذارد. موارد زیرساختی باید پس از انتخاب/راه‌اندازی بک‌اند واقعی (مثلاً Supabase Edge Functions یا سرور جداگانه) تکمیل شوند.
