YXNGJU V43 — گزارش اصلاحات و بازبینی امنیتی ایستا
تاریخ: 20 نوامبر 2026
مبنای کار: بسته V42_COMPACT_SWIPE_NAV

خلاصه
- این بسته یک وب‌سایت استاتیک برای GitHub Pages است.
- در سورس بررسی‌شده backend، ورود کاربر، پایگاه داده، API خصوصی یا پردازش سمت سرور وجود ندارد.
- بنابراین مواردی مثل کنترل دسترسی سمت سرور، احراز هویت مدیر، حفاظت API، محدودسازی درخواست، لاگ سرور و آپلود امن فایل در این پروژه قابل ارزیابی/اعمال نیستند؛ چون چنین اجزایی در این بسته وجود ندارند.
- این بررسی ممیزی ایستا و اصلاح کد است؛ تست نفوذ زنده، اسکن هاست/GitHub، بررسی حساب GitHub، DNS، TLS، هدرهای واقعی پاسخ یا دستگاه کاربر انجام نشده است. نبود آسیب‌پذیری تضمین نمی‌شود.

اصلاحات V43
1) منوی کناری در دسکتاپ و موبایل حداکثر ارتفاع صفحه دارد و اسکرول عمودی مستقل دارد.
2) اسکرول داخلی ترمینال، ویرایشگر، گالری‌ها و نواحی دارای data-native-scroll پیش از جابه‌جایی صفحه بررسی می‌شود تا ژست ناخواسته کمتر شود.
3) افکت انتقال از طریق ساخت عناصر DOM و textContent ساخته می‌شود، نه innerHTML.
4) پیام‌های پایان بازی از innerHTML پویا به textContent تبدیل شدند؛ امتیاز فقط به متن تبدیل می‌شود. نمایش شکست خط با white-space:pre-line حفظ شد.
5) CSP به صورت meta در صفحه اصلی و پورتال بازی اضافه شد: منابع پیش‌فرض self، اتصال شبکه مرورگر بسته، object و base-uri محدود، فرم‌ها فقط self. به دلیل وجود اسکریپت‌های inline موجود، unsafe-inline برای script باقی مانده و این سیاست جایگزین هدر CSP سمت سرور نیست.
6) Referrer-Policy و Permissions-Policy به صورت meta افزوده شدند.

یافته‌های امنیتی مهم
- فایل cyberlab.js فقط پیش‌نویس کد را در localStorage مرورگر ذخیره می‌کند. هیچ رمز، توکن یا داده حساس نباید در آن وارد شود.
- Cyber Lab در این نسخه فقط نمایشگر/ویرایشگر آفلاین و شبیه‌ساز فرمان است؛ کد واردشده اجرا نمی‌شود و به Python، فایل‌سیستم یا شبکه وصل نیست.
- چند محل innerHTML در بازی قبلاً برای متن‌های ثابت/امتیاز بازی استفاده می‌شد؛ این موارد به textContent تبدیل شدند. محل پاک‌سازی ترمینال با innerHTML='' فقط محتوا را خالی می‌کند و داده کاربر را تفسیر نمی‌کند.
- سایت استاتیک، ورود یا پنل مدیریت امن ندارد. هر اطلاعاتی که در فایل‌های عمومی ZIP یا مخزن GitHub قرار گیرد عمومی است. کلید API، رمز، کوکی، توکن یا اطلاعات خصوصی را هرگز در این مخزن قرار ندهید.
- لینک‌های خارجی Instagram و Telegram در HTML دارای rel=noopener noreferrer هستند.
- سیاست CSP متا نمی‌تواند همه هدرهای امنیتی را جایگزین کند؛ به‌ویژه X-Content-Type-Options، HSTS، frame-ancestors و تنظیمات سمت هاست باید جداگانه در لایه میزبانی بررسی شوند. GitHub Pages کنترل کامل همه هدرها را به صاحب سایت نمی‌دهد.

بررسی‌های اجراشده در این محیط
- Node.js syntax check: navigation.js، cyberlab.js، entity.js، home-gallery.js، x01-motion.js، yxngj-effects.js موفق.
- اسکریپت inline بازی: بررسی نحوی موفق.
- مسیر فایل‌های محلی HTML/CSS/JS/تصاویر: بررسی خودکار در ادامه ساخت بسته.
- ZIP integrity: پس از بسته‌بندی بررسی می‌شود.

محدودیت و کارهای بعدی برای ارزیابی حرفه‌ای
- تست مرورگر واقعی روی ویندوز و موبایل، آزمون صفحه‌خوان/کیبورد، تست عملکرد و بررسی دستی بازی هنوز لازم است.
- برای ادعای «راه نفوذ» باید گزارش دقیق متخصص شامل URL/مسیر، درخواست و پاسخ، شرایط بازتولید، اثر و شدت ارائه شود. این بسته به‌تنهایی امکان اثبات/رد ادعای تست نفوذ را نمی‌دهد.
- اگر در آینده backend، فرم آپلود، ورود، API یا پنل مدیریت اضافه شد، آن بخش‌ها باید جداگانه threat-model و تست شوند.
